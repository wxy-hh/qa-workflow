研发与真实浏览器真机测试闭环工作流实战教程

杜绝“单测假绿灯、线上全白屏”、“口头提需求、上线推倒重来”。本课程完整拆解基于 Matt Pocock Skills 开源体系 深度演进的端到端工程闭环：涵盖需求高压盘问、双轨联动规划、三大编码范式、真实 Chromium 浏览器真机验收门禁与双轴代码审查。

🎯 学习目标：掌握 7 大阶段执行、三大编码范式与真实验收 ⏱ 建议学习时长：20 分钟 📦 关联仓库：AI-aggregation Monorepo

1 为什么必须建立这套工作流？

传统粗放 AI 编码的恶性死循环
  • 盲目直接写码：一句话需求，AI 乱改十几个文件，跑起来发现方向完全跑偏。
  • 单测假绿灯忽悠：纯内存 Mock 单测全绿，但真实浏览器里样式遮挡、水合假死、白屏崩溃。
  • 环境故障盲改代码：上游大模型欠费 403 或端口未起，误当成业务代码写错而盲目推倒。
  • 交付靠猜无凭无据：PR 仅附一两句口头描述，代码审查者根本不知道到底测过没有。
高确定性闭环破解之道
  • 未对齐不写码：先触发 /grill-with-docs 审问边界并落盘不可篡改的 spec.md。
  • 真实浏览器真机验收：核心链路必须用真实 Chromium（ego-browser）逐条冒烟并抓图落盘。
  • 三层隔离探针定界：先探活，用单文件微脚本分层隔离网络防火墙、官方 SDK 与业务逻辑。
  • 双轴审查与证据闭环：Standards 规范轴 + Spec 需求轴硬门禁，PR 自动嵌入对比截图。

理论奠基与演进：Matt Pocock 原版体系 vs 本项目实战改造

github.com/mattpocock/skills

本工作流思想奠基于英国著名前端架构师 Matt Pocock 的开源技能体系。我们在继承其需求盘问、规格确立、TDD 与双轴审查核心思想的基础上，针对全栈 Web 业务实战进行了六大维度的系统性改造跃迁：

对比维度 Matt Pocock 原版技能体系 本项目实战改造 (AI-Aggregation)
1. 验收硬防线 纯内存单测（Vitest/Jest）全绿闭环 真实浏览器真机验收门禁 (阶段 5)：优先前台可视 Chromium (ego-browser) 抓图落盘
2. 规划视点 开发者顺向单轨，直接由 spec 拆工单编码 研发轨 (3A) 与测试轨 (3B) 双轨联动：自动派发 /qa-test-planner 提前锁定冒烟用例与断言契约
3. 协作轮次摩擦 默认单工单逐步推进，每做完一张停下等待确认 批量冲刺 (--all) 与并发派发 (/implement-spec)：自动拓扑推进，将 10+ 轮交互打断压缩至 1 轮
4. 代码审查机制 原创 Standards + Spec 双轴子代理，侧重产出建议 交付前硬门禁 + 三档分流闭环：注入平台安全/移动端44px规范，改动触及核心强制重回真机复验截图
5. 工作区落盘 GitHub 强依赖，交接文件默认存系统 /tmp 纯本地 Markdown Tracker (.scratch/)：零外部依赖，交接严格收敛于工作区，严禁散落至临时目录
6. 组织协同范式 松耦合、供开发者按需手动调用的“热插拔技能箱” 制度化流水线 + 快慢车道自适应工程剪裁：快车道小改动免大 Spec 秒级直达，核心链路制度化守死底线
双轮驱动的完整工程心智模型
🚊 轮子一：工作流主干道 (qa-workflow.md) ── 保交付下限 规定“什么时候做什么”，通过真机卡点、双轴审查和截图证据链，筑牢工程交付的基准质量红线。
🕹️ 轮子二：思维快捷键 (prompt-shortcuts.md) ── 拔认知上限 不让流水线自动跑过度设计，而是为工程师配备「第一性原理」、「对抗性审查」等杠杆短语，在关键节点按需打破盲区。

2 技能权限矩阵：命令到底由谁来触发？

开发者独占闸门命令（模型被禁调）

声明了 disable-model-invocation: true，模型绝对无法自主发起调用，必须由人类在对话框手动敲入：

/grill-with-docs — 启动需求高压盘问并产出 ADR
/to-spec — 锁定技术规格 spec.md 契约
/implement / /implement-spec — 授权开工编码
/handoff — 浓缩会话生成工作区交接文档
/grill-me — 轻量级思维漏洞推演
🛡️ 防呆理念： 防止模型“自问自答、自写规格、自行验收”，确保人类工程师始终掌控架构决策权。
通用协同技能（双向均可调用）

模型可在流水线中按需自主触发，开发者也可随时手动输入调用：

qa-test-planner — 规格生成后自动规划测试集
tdd — 编码阶段驱动单测红-绿-重构循环
ego-browser — 自动拉起前台真实 Chromium 冒烟抓图
diagnosing-bugs — 冒烟遇到 FAIL 时自动诊断排障
code-review / pr / retro
💡 提示： 日常遇到怪异报错随时敲 /diagnosing-bugs；调试前端随时敲 /ego-browser。

核心进阶：阶段 4 的三大实现范式

模式 A：单工单调试模式 /implement 工单 01

单任务做完即停，向人类汇报并交出控制权。适合高危架构重构或疑难缺陷探索。

模式 B：单会话批量冲刺 (推荐) /implement --all

在当前分支顺次沿 DAG 依赖全速实现，状态自动翻转为 done，单测全绿后主动流转阶段 5。

模式 C：并发派发模式 /implement-spec

自动拉出集成主分支，为每个前沿工单派发独立子 Agent（专属 Git Worktree 并行跑 TDD），Merger 滚动合流。

阶段 5 真实浏览器验收卡点

为什么单测绿灯无法替代真机？ 纯内存测试无法探测 CSS 层叠遮挡、DOM 点击冒泡拦截与 React SSR 水合假死。

• 端口探活：curl -s http://localhost:3030 优先防伪绿
• 水合锚点：严禁 networkidle，以特征输入框挂载为就绪准绳
• 工具首选：macOS 优先 ego-browser（真实Cookie/可人工接管）；CI 环境降级 Playwright
• 时间盒纪律：≤ 5 条 P0 冒烟 / ≤ 15 分钟
阶段 6 双轴代码审查门禁

规范轴与需求轴并行审查：双轴分别由两个子代理独立运行，防止互相掩盖。

• 规范轴 (Standards)：Fowler 12 大坏味道（冗余代码、过度设计、中间人）+ 安全零泄漏 + 移动端 44px 热区 + 全量中文
• 需求轴 (Spec)：核销全部 User Stories，遗漏直接判 FAIL
• 三档分流处置：本次修（触及核心重回复验截图）/ 转专项（入遗留事项）/ 驳回（ADR 已有决策）

4 思维快捷键工具箱与快慢车道剪裁

🕹️ 4 大认知纠偏思维快捷键

用于打破大模型顺从讨好与局部修补偏置的一句话杠杆（按需使用，不强加于流程）：

1. 对抗性审查（阶段 1） 「对这个方案做对抗性审查，优先寻找能推翻核心假设的反例，不要帮它找理由。」
2. 第一性原理（阶段 1/2） 「不要基于现有方案继续设计，从第一性原理重新分析这个问题到底该怎么解。」
3. 奥卡姆剃刀（阶段 6 审查） 「调用 /improve-codebase-architecture 运行 Deletion Test，清除无意义抽象层。」
4. 消融实验（阶段 7 交付） 「给这几项改动设计消融实验，逐项评估独立贡献，删除搭便车的伪优化。」

🚦 三档车道自适应工程剪裁

拒绝教条主义，按改动规模与协作形态自适应分流：

🟢 快车道 (Fast Track) 纯文案、极简样式或单点小修复 ──> 免写大 Spec，直接 /implement + TDD，单测保证接缝，秒级交付。
🟡 标准车道 (Standard Track) 单会话独立新功能 ──> /to-spec ➔ /qa-test-planner ➔ /implement（跳过 3A 碎工单直接从 spec 推进）➔ 浏览器真机验收 ➔ 双轴审查。
🔴 慢车道 (Full Track) 跨模块、跨人交接或大型深重构 ──> 完整 7 阶段全流程，拆解工单 DAG，全量证据链归档。
🛡️ 六大红线底线：凡触及认证、流式对话、图像、视频、语音、计费，阶段 5 真机验收绝不可剪裁！

5 跨会话交接契约与排障心法

标准化交接文档机制 (/handoff 技能)

严禁将交接文档散落到系统临时目录（/tmp）！技能已强制收敛于项目工作区：

同机跨会话续接 (单机流转) .scratch/<feature>/handoff.md
与 spec.md 和 qa-plan.md 同级归档，不污染代码树。
跨团队成员交接 (版本化入库) docs/handoff/YYYY-MM-DD-slug.md
随 Git 提交入库，组员 pull 后可直接读取接力。
💡 新会话接力指令： 「请阅读交接文档 .scratch/<feature>/handoff.md，严格按建议技能继续推进。」

遇到上游接口报错时的“三层隔离探针链”

遇到大模型报错（如 No output generated 或 403 欠费）时，切忌盲目乱改业务代码！在工作区写一个微脚本（如 .scratch/<feature>/probe-ark.mts）层层定界：

一层：裸 curl 直连 直连官方域名 OpenAPI，排查欠费、防火墙或网络代理阻断。
二层：官方 SDK 微脚本 调用官方最简示例，排查 API Key 与签名算法版本兼容性。
三层：项目适配器接缝 前两层皆通，方可接入本地 Adapter 锁定数据格式与代码逻辑。
